# CLAUDE.md

Стереокамера для Android: две задние камеры (широкоугольная + основная) → SBS фото и видео.
Основное тестовое устройство — Pixel 9 (`tokay`). Обзор возможностей и архитектуры — в README.md.

## Сборка и запуск

JDK в системе нет, используем JDK из Android Studio:

```bash
export JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home"
./gradlew assembleDebug
```

`adb` не в PATH: `~/Library/Android/sdk/platform-tools/adb`.
Телефон подключается по беспроводной отладке, иногда виден дважды (mDNS-имя и IP:порт),
поэтому серийник задаём явно: `export ANDROID_SERIAL=<id из adb devices>`.
После перезагрузки телефона беспроводную отладку нужно включить заново (порт меняется).

```bash
adb install -r app/build/outputs/apk/debug/app-debug.apk
adb shell am start -n com.example.my_3d_camera.dev/com.example.my_3d_camera.MainActivity
```

- Release: `./gradlew assembleRelease` → `app/build/outputs/apk/release/app-release.apk`,
  id `com.example.my_3d_camera.release`, подписана debug-ключом (`~/.android/debug.keystore`) —
  только для личной установки. Debug-версия называется на телефоне «Stereo Camera dev»
  (`app/src/debug/res/values/strings.xml`). Настройки калибровки у сборок раздельные.
- Debug-сборка имеет id `com.example.my_3d_camera.dev`. На телефоне также стоит старая версия
  `com.example.my_3d_camera` с другим ключом подписи и ~1 ГБ видео в её личной папке.
  **Не удалять её без согласия пользователя** — Android сотрёт эти видео.
- Отладочный параметр: `--es wide_size 2048x1536` принудительно задаёт поток широкоугольной камеры.
  `am start` не перезапускает уже открытую активити — для нового параметра сначала
  свернуть (`input keyevent KEYCODE_HOME`), затем `am force-stop`, потом `am start`.

## Как проверять на телефоне

- Карточка статуса над превью (столбиком): размер SBS, поток широкоугольной, fps собранных пар,
  рассинхрон внутри пары, кадры без пары. Читать её: `adb shell uiautomator dump` + grep `statusValues`
  (uiautomator сам нагружает телефон — для точных замеров лучше временный `Log.d` из `onStats`).
- Кнопки нажимаются через `adb shell input tap X Y` (координаты брать из uiautomator dump).
- Скриншот: `adb exec-out screencap -p > shot.png`.
- Видео и фото лежат в `/sdcard/DCIM/3D Camera` (раньше — `Movies/` и `Pictures/`, при запуске переносятся);
  список: `adb shell content query --uri content://media/external/video/media ...`.
  ffprobe на маке нет — частоту кадров MP4 считали python-парсером таблицы `stts`.
- Характеристики камер: `adb shell dumpsys media.camera`.
- Замеры делать по 10–15 секунд и закрывать приложение между ними (см. перегрев).

## Факты о камерах Pixel 9

- Логическая задняя камера `0` с физическими `2` (основная, 6.9 мм), `3` (широкоугольная, 2.02 мм)
  и `4` — служебная «основная с 2x-кропом сенсора», её `LENS_INTRINSIC_CALIBRATION` некорректна.
  Поэтому пара выбирается по фокусному расстоянию и физическому размеру сенсора, а калибровка
  используется, только если согласуется с физикой (`StereoRig.describe`).
- Широкоугольная стоит на 16 мм левее основной (`LENS_POSE_TRANSLATION`, ось X) → в портрете это левый глаз.
- Кроп широкоугольной до поля зрения основной ≈ 1.976.
- `SENSOR_INFO_TIMESTAMP_SOURCE = REALTIME`, синхронизация сенсоров `APPROXIMATE`:
  реальные экспозиции расходятся на 10–28 мс. Это предел железа.
- Физические камеры принимают ключи: sensitivity, exposureTime, colorCorrection gains/transform,
  zoomRatio, focusDistance, aeExposureCompensation.
- JPEG у обеих физических камер — до 4032×3024 (`ImageFormat.JPEG` в карте физической камеры).
- Аппаратный H.264-энкодер `c2.exynos.h264.encoder` — до 7680×4320.

## Грабли (уже наступили)

- **Перегрев.** Порог LIGHT — 39 °C корпуса, MODERATE — 43 °C. Начиная с него HAL снижает fps,
  а затем перестаёт отдавать кадры одной из физических камер (буферы приходят как `onCaptureBufferLost`).
  Выглядит как «сломалось» — сначала проверить `adb shell dumpsys thermalservice`.
- **`CONTROL_ZOOM_RATIO` для физической камеры ломает поток второй камеры** (её кадры перестают приходить).
  Не использовать. После таких экспериментов камерный стек может «зависнуть» до перезагрузки телефона.
- **fps зависит от размера потока широкоугольной**: 4032×3024 → ~25, 2560×1920 → ~28, 2048×1536 → ~29–30
  (даже на холодном телефоне). Поэтому видео — с потоков 2048×1536, а фото — отдельным
  полноразмерным JPEG-запросом (`StereoCamera.captureStill`). Сессия в режиме фото: 2 потока превью
  2048×1536 + 2 JPEG 4032×3024 (HAL принимает, превью ~23 fps). Если HAL не примет JPEG-потоки,
  фото снимается из GL-кадра (`StereoRenderer.capturePhoto`) с большим потоком широкоугольной.
  Коррекция дисторсии (`DISTORTION_CORRECTION_MODE_FAST`) стоит ~1 fps, но нужна для геометрии.
- **Кадры двух камер приходят вразнобой** (до 4 кадров разброса, пачками). Нельзя держать кадр
  в очереди SurfaceTexture в ожидании пары — камере не хватит буферов. Поэтому кадр сразу забирается
  и рисуется в кольцевой буфер (`StereoRenderer.EyeStream`), пары ищутся там по метке времени.
- С включённой коррекцией дисторсии HAL отдаёт обоим кадрам одного запроса одинаковую метку;
  без неё метки физических камер различаются на 10–28 мс и допуск склейки (15 мс) перестаёт работать.
- Интерфейс — Material 3 (`material:1.13.0`, тема `Theme.Material3.DynamicColors.Dark`):
  цвета берутся из обоев, как в Google Камере. Кнопка спуска — свои drawable `shutter_*`.
  Кнопки в разметке объявлять как `MaterialButton`, а не `<Button>`, иначе view binding
  даст тип без `isChecked`. У `ShapeableImageView` не менять отступы на лету — маска формы не пересчитается.
- Геометрия совмещения реализована дважды: в шейдере (`StereoRenderer.renderEye`) и в
  `StillComposer.eyeMatrix` для полноразмерного фото. Меняя одну — менять и другую.
- Сборка фото 6048×4032 на CPU требует ~160 МБ памяти, поэтому в манифесте `largeHeap`.
- Камера должна закрываться в `onPause`; порядок закрытия: запись → камера → рендерер.

## Соглашения

- Комментарии и логи — на русском, весь текст интерфейса (включая сообщения об ошибках) — на английском.
- Логика камеры/GL/медиа — в своих пакетах, `MainActivity` только UI и жизненный цикл.
- Перед изменениями в камере/рендерере — проверять на телефоне, а не только сборкой.
- Временную отладку убирать перед коммитом.

## Открытые задачи

- Выровнять экспозицию и баланс белого между глазами (через физические ключи камеры).
- Проверить длительную запись (нагрев, размер файлов).
- Перенести видео из старой версии приложения (они в её личной папке `Android/data/...`),
  затем её можно удалить. 68 фото старой версии лежат в общем `Pictures/` и при удалении сохранятся.
- Возможна вертикальная рассогласованность из-за поворота объективов (`LENS_POSE_ROTATION` не учитывается).
