# Stereo Camera

Android-приложение для съёмки стереофото и стереовидео в формате Side-by-Side (SBS)
на две задние камеры телефона: широкоугольную и основную. Проверялось на Pixel 9.

## Возможности

- Превью, фото и видео сразу в SBS: кадр собирается на GPU в реальном времени, склейка после записи не нужна.
- Видео пишется одним MP4 со стереозвуком прямо в галерею, фото и видео — в одну папку `DCIM/3D Camera` (один альбом).
  Суффикс `_SBS` в имени помогает VR-плеерам распознать формат.
- Кадры двух камер склеиваются по времени съёмки, рассинхрон и пропуски видны в строке статуса.
- Широкоугольный кадр автоматически кропается до поля зрения основной камеры
  по калибровке объективов (`LENS_INTRINSIC_CALIBRATION`), порядок глаз берётся из `LENS_POSE_TRANSLATION`.
  Есть ручная подстройка масштаба и сдвига по вертикали (кнопка справа внизу) и кнопка «Поменять глаза местами».
- Режимы:
  - **Фото** — по кнопке обе камеры одним запросом снимают полноразмерный JPEG (4032×3024),
    SBS 6048×4032 собирается на CPU (`StillComposer`) с той же геометрией, что и превью;
  - **Видео** — соотношение сторон и частота кадров выбираются отдельно в панели «Video settings»
    (кнопка с текущим форматом справа от спуска, панель — по образцу Google Камеры):
    - **4:3** — одинаковые потоки обеих камер 2048×1536, SBS 3072×2048, только 30 fps;
    - **16:9** — основная 1920×1080, широкоугольная 3840×2160, SBS 2160×1920, 30 или ~57 fps.
      После кропа широкоугольной глаза одинаково резкие, но поле зрения по горизонтали на 25% уже.
    60 fps камера отдаёт только в 16:9, поэтому выбор 4:3 переключает на 30 fps, а выбор 60 fps — на 16:9.
- Предупреждения о нагреве: при перегреве Android снижает частоту кадров и может отключить одну из камер.

## Как устроено

```
camera/StereoRig       выбор пары камер, геометрия совмещения, размеры потоков
camera/StereoCamera    логическая камера, одна сессия с двумя физическими потоками
gl/StereoRenderer      приём кадров, кроп в кольцевые буферы, склейка пар, отрисовка SBS
gl/EglCore, GlUtil     EGL-контекст (совместимый с энкодером) и GL-утилиты
media/SbsVideoRecorder MediaRecorder с входной поверхностью, запись сразу в MediaStore
media/StillComposer    сборка полноразмерного SBS-фото из двух JPEG
media/MediaSaver       сохранение фото и видео в галерею
MainActivity           UI и жизненный цикл
```

Кадры двух камер приходят вразнобой (разброс до нескольких кадров), поэтому рендерер сразу забирает
каждый кадр у камеры, рисует его обрезанным в кольцевой буфер «глаза» и собирает пары с одинаковой
меткой времени. Метка времени кадра камеры передаётся в энкодер, поэтому звук и видео не расходятся.

## Ограничения (Pixel 9)

- Расстояние между объективами — 16 мм (у человека ~63 мм), поэтому объём заметен в основном на близких планах.
- Сенсоры синхронизированы «приблизительно»: реальные моменты экспозиции двух камер расходятся на 10–28 мс.
- 60 fps камера отдаёт только на потоках 16:9, на 4:3 — не больше 30. С большим потоком 4:3 широкоугольной
  камеры не выходит и 30 fps, поэтому видео 4:3 пишется с потоков 2048×1536 и левый глаз в нём примерно вдвое
  мягче правого (в 60 fps / 16:9 этой проблемы нет). В фото оба глаза из полноразмерных JPEG,
  но левый всё равно мягче: ультраширик кропается в ~2 раза.
- После 10–15 минут непрерывной работы двух камер телефон перегревается.

## Сборка

Открыть в Android Studio или собрать из командной строки:

```bash
./gradlew assembleDebug
```

Debug-сборка ставится с id `com.example.my_3d_camera.dev`, чтобы не конфликтовать с ранее установленной версией.
Для замеров можно принудительно задать размер потока широкоугольной камеры:

```bash
adb shell am start -n com.example.my_3d_camera.dev/com.example.my_3d_camera.MainActivity --es wide_size 2048x1536
```

Требования: Android 11+, логическая камера с двумя задними физическими камерами.
